# Visual director implementation plan

The existing Next.js studio submits durable jobs to a Node worker (local polling or BullMQ). Research uses guarded Playwright pages and source-backed claims. Exploration captures heading-based scenes. Script generation uses Codex/API or extracts quotes. Kokoro supplies the master audio and segment/word timestamps. The director currently emits one browser shot per segment; recording unconditionally scrolls every clip. FFmpeg and portable HyperFrames compositions frame all footage identically. Atomic stage and clip artifacts enable restart, scoped regeneration and QA repair.

Preserve this pipeline. Extend inventory with independent media, code, sections and demo candidates. Retrieve original raster/GIF/video assets with guarded bounded downloads; capture unsupported media/elements separately. Keep scene IDs for existing script evidence. Refresh legacy inventory without regenerating voice.

Build short narration-aligned shot slots and rank source-matched assets by semantic support, quality and recent use. Optionally use the configured model to choose visual intent and evidenced diagram relationships. Validate model selections and fall back to deterministic planning. Persist the selected assets, rationale, focal regions, motion, captions, diagnostics and fallback reasons. Opening prefers relevant product media. Navigation actions happen before the recorded trim; visible scrolling is explicit, bounded and never consecutive.

Execute each shot independently. Checkpoint by shot signature, not just ordinal ID. Static assets become camera clips with deterministic FFmpeg crops/pushes/pans; both editing backends consume these clips. Browser demos replay known actions without automatic scrolling. Diagrams/code use locally rendered source-backed scenes. Context, product and detail modes retain dark blue identity. Captions overlay with per-shot safe positions and split at cuts.

Validate timeline coverage, supported asset/type combinations, scroll limits, source/framing repetition, motion repetition, focal/caption collisions and hook quality before capture. Final QA retains stream/audio/black/evidence checks and adds plan integrity, actual capture quality and delivery encoding. Repairs retain successful shots.

Verification: regression/unit tests for timing, semantic selection, repair/rejection and captions; real Chromium/FFmpeg integration for inventory discovery, every executable shot treatment, camera frame changes, checkpoint reuse and independent failure; full existing suite, typecheck, production build and real Kokoro smoke when available. Save a representative output and inspect plan and frames. No automatic commits or provider/model changes are needed.

## Implemented and verified

The director supports establish, scroll_to, media_fullscreen, zoom_region, pan_media, highlight, click_demo, video_playback, code_focus, feature_card and diagram. Camera crops and annotations use normalized source coordinates. Motion is deterministic, source playback is normalized to 30fps without changing its speed, and diagrams reveal nodes/edges sequentially before the final hold. Browser clips retain their raw recordings and can also receive post-production camera treatment. Captions are split at cuts and use four safe placements.

The studio exposes final intent and reasons in its Shots tab. `inventory.json`, `shot-plan.json`, `director-report.json`, `diversity.json`, source previews, captured sources, raw recordings, capture signatures, per-shot edit checkpoints, transcript and QA remain inspectable. Visual regeneration starts at directing, preserving narration.

A real PhotoCraft GitHub run discovered 25 assets and produced 16 shots over 60.65 seconds with no visible scrolling and passing QA. The image-aware pass used product crops, a mask highlight, layer-dialog close-ups, source code excerpts and contextual cuts. The proposed architecture diagram was declined by the evidence gate; its renderer was exercised independently. Full FFmpeg and a short HyperFrames render were verified. Both full compositions passed HyperFrames lint/runtime/layout/contrast checks. Real Kokoro smoke and edit restart passed. Tests cover every executable shot type, real camera pixels, isolated retries, stale signature rejection, code/source changes, word mapping, scroll budgets, framing diagnostics, captions, media discovery and provider image attachments.

Remaining limits: exploration and demo probes are bounded; no authenticated flows, CAPTCHA solving, native repository installation or DRM playback; precise semantic pixel QA remains human review. Image previews cover up to eight ranked assets per model call. Repeated stationary treatments on different informative code/image sources remain diagnostic warnings rather than forcing effects. HyperFrames rendering needs Node >=22.12; verification used installed Node 24.
